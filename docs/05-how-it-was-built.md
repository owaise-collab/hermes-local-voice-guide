# 5. How this setup was built

This is the breakdown of the actual implementation, rewritten for reuse rather than copying one person's user-data directory.

## Stage 1: inspect before installing

We checked the existing Hermes installation, its configuration, the available llama.cpp binaries, model files, and GPU detection. Hermes was already configured for a loopback endpoint but could not start its selected Python environment. The binaries detected an 8 GB Radeon RX 5700 through Vulkan.

The first fix was `hermes pm repair`, using Hermes's own package manager. That restored its managed environment. We did not replace system Python or install random packages into an existing venv.

## Stage 2: make local inference real

An existing Qwen3-4B GGUF allowed an initial server smoke test. We started llama.cpp on loopback with a model alias, GPU offload, a chat template, and one slot.

The first 32K setting failed Hermes's context floor. Raising the requested window was not sufficient for the older model because the server capped its usable context. We selected the official Agents-A1-4B Q8_0 GGUF, checked its exact revision and SHA256, and verified the running server reported the full 65,536-token window.

The model was chosen for an agent-focused workload under a 6B budget. The developer's benchmark claims informed the choice, but the setup depended on local tests: an actual structured tool call and a Hermes terminal command. Neither a benchmark table nor a healthy HTTP endpoint was treated as proof that agent tools worked.

## Stage 3: add discovery without breaking Hermes's conventions

We fetched Vercel's `find-skills` from GitHub through the native installer. Its security scan returned SAFE for that downloaded content. We kept the discovery approach but replaced the upstream installation command with Hermes's own skill manager.

That matters because an ecosystem CLI can install skills into another agent's folders. A file being downloaded is not the same as Hermes being able to discover and load it. We tested both the public catalog search and the local model's ability to read the installed skill and return its correct source and native command.

This public kit contains the reviewed adaptation and attribution, with portable paths. It does not contain the original machine's skill lockfiles, prompt snapshots, or private skills.

## Stage 4: teach a result-oriented team workflow

Hermes already had `delegate_task`; no custom agent framework was necessary. We enabled its native toolsets, kept child model routing local, limited child concurrency to one, and provided a short role/workflow skill.

The parent passes exact context to a Researcher, Builder, or Reviewer task, receives completion, inspects artifacts, and verifies results. The appended SOUL text reinforces finishing work and reporting evidence. Skills are read on demand rather than flooding every prompt with a large instruction catalog.

We tested a real child writing a harmless file. The parent received the asynchronous completion, read the file, and confirmed its expected content. A successful child status alone was not the acceptance check.

## Stage 5: add local speech

We installed Hermes's `voice` and `piper` extras through PM. Faster-Whisper `base` runs with CPU int8 and VAD. Piper uses `en_US-lessac-medium` on CPU. Keeping speech off the GPU reserves VRAM for the LLM and avoids pretending that an AMD Vulkan inference setup is a CUDA speech setup.

We configured Ctrl+B, automatic spoken replies when voice mode starts, a two-second silence interval, and an explicit stop phrase. No new paid speech key was required. The setup uses standard Hermes voice mode rather than an unrelated always-listening program.

## Stage 6: test each link in the chain

We separated:

1. Speech generation into a WAV.
2. Transcription of a known synthetic sentence.
3. Audio input device enumeration and actual microphone access.
4. Live microphone transcription.
5. Speaker playback.
6. A local Hermes model generating its own spoken confirmation through the TTS tool.

The original machine first had no visible recording input. We did not mask that as a software success. Once a working headset input appeared, microphone capture and live transcription passed. The spoken confirmation was generated by Hermes and played through the selected output.

## Stage 7: package the reproducible parts

The repository substitutes parameters for personal absolute paths, discovers the selected Hermes runtime through its package-manager interfaces, and keeps user configuration backups outside the Git working tree. Its configurator preserves unrelated settings and appends rather than replaces SOUL instructions.

It includes tests for configuration merge behavior, dry-run behavior, idempotence, backups, and invalid local endpoints/context. It does not distribute credentials, original user config, session databases, model binaries, raw logs, or recordings.

## Tradeoffs to keep

- A 4B agent remains fallible. Skills provide procedures, not guaranteed reasoning quality.
- Child agents isolate context but share the same compute and local files. More children are not free parallel hardware.
- Local inference still has startup, prompt-processing, speech recognition, and synthesis latency. This is not a benchmarked low-latency assistant.
- First-run downloads need the internet. Public skill search and web tools are online features.
- The exact full stack was verified on one Windows setup. Other platforms and hardware need their own validation.
